  THE CONCEPTS WERE STATED BEFORE ANY CODE WAS WRITTEN, as instructed.

  THE TRAP, in one sentence: one document-level mechanism with zero per-modal
  code -- a MutationObserver on each .modal's class records
  document.activeElement as the return target the moment the modal gains .on
  and restores it when .on is removed, while a single keydown handler cycles Tab
  inside whichever .modal.on is open, RECOMPUTING THE FOCUSABLE LIST AT KEYPRESS
  TIME rather than caching first and last.

  THE ANNOUNCEMENT, in one sentence: nav() writes the newly shown panel's OWN
  VISIBLE .ptitle text into one aria-live="polite" region, so the spoken name is
  derived from the heading the sighted user sees and cannot drift as panels are
  added.

  trap "needs per-modal first/last bookkeeping and a return-focus target, and

  recomputed at keypress time -- and that version is ALSO the only one that
  stays correct for the modals here whose controls appear while they are open
  (tx-plan items, the denial form, the payer-terms list). The weaker design was
  the one that needed the bookkeeping.
