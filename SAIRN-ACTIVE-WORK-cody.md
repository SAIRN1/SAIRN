  **THE ASYMMETRY WITH `retainage_pct` IS THE CAREFUL BIT.** A missing PERCENTAGE is **not** zero -- *"we hold nothing"* and *"nobody recorded what is held"* are different facts, and that rule was already in this engine. A missing RELEASE **genuinely is zero**: retainage is held by default and released by an event, so no event recorded means none happened. **Zero is also the conservative direction** -- it says money is still being withheld, which is the answer that makes somebody go and check.

  **FOUR FAILURE MODES SURFACED RATHER THAN CLAMPED**, matching the rule overpayment already followed in this file. A release with **no date** is RECORDED and flagged -- refusing it would lose a real payment, but it cannot be aged or reconciled. A release **larger than was ever held** reports `retainage_over_released` and says so. A **negative** release is refused as a typo, never treated as an increase. And with **no usable percentage**, outstanding is NULL rather than the released figure, because reporting only what came out would imply the rest is settled. **The undated and over-released cases are also raised at JOB level** -- a summary screen never reads the problems list of a single draw.
