    rt_routes_source_check

`sql/rt_routes_schema.sql:14` says, as fourth's b38 reconciliation *"to what
Michael actually ran"*: **"`constraint rtroutes_saved_sane` was REMOVED before
the run, deliberately."** It is not removed. It is on the database.

own argument at :90-102 is that `api/_lib/routes.js` returns a **negative**
saving **un-clamped on purpose** — *"a caller that stores a negative saving has

had."* The file then states what the constraint would do: *"With the constraint
in place Postgres would have rejected the ENTIRE upsert and the route write
would have failed."* **The constraint is in place.** So the first negative
saving to reach the live database fails the whole upsert, and the repo's own
documentation says that cannot happen. Nobody will look at the schema file

**ROUTED, NOT FIXED:** `sql/rt_routes_schema.sql` is fourth's and outside cc's
