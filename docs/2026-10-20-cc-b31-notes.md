## 4. ITEM 2: THE --save BUG WAS NOT WHERE b30 SAID, AND THERE WERE TWO

**b30's claim, that "a multi-path --save writes nothing", was WRONG.** Two
paths in one call both saved.

**The real defect:** the save ran **after** the full render was printed.
b30's call was piped through `head -40`, which closed stdout early, so
BrokenPipeError killed the process inside the render, before any write. That
was my own pipe.

Reproduced failing-first: 8 paths through `head -3` saved **0 of 8**.

Concept, stated before the code:

> A save must not depend on anybody reading the report. Write first, print
> second.

`_save_drafts()` now writes every draft and returns its report lines. Main
prints them after the render. **Through the same closed pipe: 8 of 8.**

**A second defect turned up while using it:** one unwritable target (a
trailing `\r` from my CRLF list) raised out of the loop. It lost every later
draft in the batch: 0 of 30, and then 0 of 81. The write is now per-target in
a `try` block, and a failure is reported as `NOT saved (<target>): could not
write ...`. Driven on the same CRLF list: 80 refusals named, the loop finished.

`--selftest` is 9/9 throughout.
