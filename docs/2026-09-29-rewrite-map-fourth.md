# Hook and tool rewrite map

Generated by `tools/rewrite_convergence_map.py --map`. Verify with
`--verify`; the convergence claim is checked by `--simulate`.

## Hooks

### `post_rewrite_hook` -- `.githooks/post-rewrite`

- **Anchor (must appear exactly once):** `--post-rewrite`
- **Trigger:** git fires it once after a rebase or an --amend completes, with the old->new sha map on stdin
- **Writes:** docs/defect-density-register.json -- re-seats cited shas. Does not stage and does not commit.
- **Can its own write re-trigger it?** NO on its own: it writes a file, and writing a file is not a rewrite, so git never fires it again. But the dirty tree it leaves blocks the amend, the push fails, and the LOOP rebases again -- which does fire it again. This is the livelock, and it is a property of the loop, not of the hook.

### `prepare_commit_msg_hook` -- `.githooks/prepare-commit-msg`

- **Anchor (must appear exactly once):** `for CHECK in staged_conflict_marker_check.py staged_credential_check.py`
- **Trigger:** every git commit, INCLUDING the commit inside git rebase --continue (pre-commit does not fire there)
- **Writes:** nothing. It refuses, non-zero, and the staged resolution stays staged.
- **Can its own write re-trigger it?** NO -- it writes nothing at all, so there is nothing for it to react to.

### `pre_commit_hook` -- `.githooks/pre-commit`

- **Anchor (must appear exactly once):** `hover_auditor_scope_gate.py" --pre-commit`
- **Trigger:** every git commit in a clone carrying the hover-auditor marker in .git/; one file test and exit in every other clone
- **Writes:** nothing. Refuses out-of-scope writes.
- **Can its own write re-trigger it?** NO -- writes nothing.

### `pre_push_hook` -- `.githooks/pre-push`

- **Anchor (must appear exactly once):** `sairn_push_gate_hook.py" --pre-push`
- **Trigger:** every push, from any caller -- Bash, a Python subprocess, an IDE. That is the property the old command-text regex never had.
- **Writes:** nothing. Refuses the push.
- **Can its own write re-trigger it?** NO -- writes nothing. It can make the loop retry, which is the loop re-entering, not this re-firing.

## Tools

### `push_retry_rebase` -- `tools/push_retry.py`

- **Anchor (must appear exactly once):** `def cmd_loop(`
- **Trigger:** python tools/push_retry.py --loop, and again on each attempt while the branch is behind origin/main
- **Writes:** rewrites local commits (the rebase). FIRES post-rewrite.
- **Can its own write re-trigger it?** YES, by design and bounded: --attempts N. The rebase is what fires post_rewrite_hook, which is the first half of the closed loop.

### `push_retry_regenerate` -- `tools/push_retry.py`

- **Anchor (must appear exactly once):** `def regenerate():`
- **Trigger:** each loop attempt, after the rebase
- **Writes:** the three GENERATED docs, and stages ONLY those. PR 2.5: a conflict in a derived document is resolved by re-deriving.
- **Can its own write re-trigger it?** NO -- re-deriving from the same source is idempotent, so a second run writes the same bytes and the tree stops changing. Its correct refusal to stage anything else is what leaves the register dirty.

### `amend_guard` -- `tools/push_retry.py`

- **Anchor (must appear exactly once):** `def amend_safety():`
- **Trigger:** before any --amend the loop would perform
- **Writes:** nothing. Exit 3 and a reason when an amend is unsafe.
- **Can its own write re-trigger it?** NO -- writes nothing. It is the step that was right to refuse and therefore right to hold the livelock open until the fold-in existed.

### `fold_reseat` -- `tools/push_retry.py`

- **Anchor (must appear exactly once):** `def reseat_only():`
- **Trigger:** each loop attempt, on a dirty register only
- **Writes:** stages docs/defect-density-register.json -- ONLY when every changed line is a "commit" citation AND defect_register.py --check passes. Anything else is left and named.
- **Can its own write re-trigger it?** NO -- once folded the register is clean, so the next attempt finds nothing to fold. THIS IS THE STEP THAT CLOSES THE LIVELOCK, which is why ablating it is the known-bad control.

### `defect_register_reseat` -- `tools/defect_register.py`

- **Anchor (must appear exactly once):** `def reseat_base(`
- **Trigger:** --post-rewrite from the hook, or --reseat by hand
- **Writes:** docs/defect-density-register.json. Never commits.
- **Can its own write re-trigger it?** NO -- a re-seat onto already-correct shas is a no-op, so it reaches a fixed point in one further pass. That fixed-point property was itself a fix: it used to accept a DANGLING commit as a good sha and skip the records a rebase had orphaned.

### `claim_commit_push` -- `tools/sairn_claim.py`

- **Anchor (must appear exactly once):** `'git', 'push', 'origin', 'HEAD:main'`
- **Trigger:** every `claim` and every `release` -- so several times a session, from any session
- **Writes:** .claude/claims/<session>.json, then COMMITS it and PUSHES, rebasing onto origin/main first when it is behind.
- **Can its own write re-trigger it?** NO by itself -- the claim file it writes is the one it then commits, and a second claim writes different content rather than the same content again. BUT ITS REBASE FIRES post_rewrite_hook exactly as the push loop does, so it can enter the livelock from a completely different door. It refuses outright on an unstaged change rather than staging by breadth, which is what keeps it out.

### `rebase_resolve` -- `tools/sairn_rebase_resolve.py`

- **Anchor (must appear exactly once):** `if pol.get('strategy') != STRATEGY:`
- **Trigger:** by hand during a conflicted rebase, on a ledger whose merge_policy it reads from the COMMON ANCESTOR
- **Writes:** the merged ledger, and STAGES it -- never commits. Stages nothing unless the ledger's own validator passes.
- **Can its own write re-trigger it?** NO -- a union of a set with itself is that set, so a second run on the merged file finds nothing to merge. It REFUSES on a deleted record or on one both sides changed differently, which is the case where a union would be a different wrong answer rather than a safer one.
