## 2. THE FINDING THE RESEARCH HAS NO CATEGORY FOR: refrigerant regulation is sub-nationally forked

`ae2367aa`, since the 09-17 pass: *"a THIRD refrigerant rule, and it is a STATE
one — CARB 17 CCR 95380."* Verified in `api/_lib/mech-assets.js`:

| Limb | Threshold | GWP floor | Scope | Citation |
|---|---|---|---|---|
| Section 608 | 50 lb | — | federal | 40 CFR 82.157 |
| AIM Act | **15 lb** | **53** | federal | 40 CFR 84.106 |
| **CARB RMP** | **50 lb** | **150** | **state, `CARB_STATE = 'CA'`** | 17 CCR 95380 *et seq.* |

**Why this breaks the research's structure rather than merely extending it.**
§4 of the 08-21 report is organised by country — US, UK, EU, Australia, Canada —
and §6 states the HVAC need as *"EPA 608 (US) / F-Gas Category I–III (EU) /
equivalents."* Both assume the regulatory unit is the **nation**. CARB is a
state program whose threshold agrees with one federal rule (50 lb) and whose GWP
floor agrees with neither (150 vs 53), so **an appliance can be in scope under
one limb and out of scope under another, in the same building, on the same day.**
The code handles this explicitly; the research has no row it would go in.

**And the code's own asymmetry is the part worth carrying into any future
version of this research**, because it is a modelling rule and not a fact about
California. From the block above the constants: *"a unit whose state is not
recorded is NOT a finding that CARB does not reach it"*, and — the direction that
matters — because CARB's floor (150) is above the AIM Act's (53), *"if a
contractor has stated the refrigerant is NOT above 53, it cannot be above 150"*,
while the converse does not hold. **A three-limb rule set is not three
independent booleans; some pairs constrain each other and some do not, and which
is which has to be derived rather than assumed.** That is the generalisable
finding, and it is the reason this belongs in a triage rather than a marker table.

**Bearing on the research's own §4: it should be re-scoped from "per country" to
"per jurisdiction that can legislate a threshold."** Not proposed as work here —
recorded so the next pass does not re-derive a country list and call it complete.

## 3. §8's dominant-pain row has moved, and it is the one row worth re-reading

§8 rates data portability and lock-in *"a bigger practical risk than
trade-specific compliance logic across every vendor examined"* — ServiceTitan's
termination-fee complaints, the Housecall Pro→ServiceTitan lost-records case,
PCI-driven card-token immobility. The 09-17 pass recorded it as **NOT BUILT AND
DISCLOSED**. At this commit it is **partially built**, and the two halves sit side
by side on purpose:

- **Real, and narrow: one dataset.** `MECH_EXPORTS` at `:2325` holds exactly
  `credentials`; `mechExportDataset('credentials')` is wired to a button at
  `:824`. `python tools/export_coverage_check.py` independently reports
  `sairnmechanical mech_credentials EXPORTABLE`.
- **Still disclosed, and honest: three buttons.** `:492`, `:656` and `:671` all
  still call `mechNotLive('CSV export','exported')`, which toasts *"CSV export is
  not live yet — nothing was exported."*

**The export's own reasoning is the more useful finding than the fact it
exists**, and it is a shape any future export should copy: it exports **the
records, not the board.** The on-screen table is `latestByKey()` — one row per
(technician, type, section-or-jurisdiction), newest wins — which is right for
answering *"is this current"* and **wrong for a file**, because the superseded
rows are the history that makes an append-only register worth having. The comment
names the precedent it is avoiding: *"SAIRNdental's ageing buckets exported in
place of the charges, one app over."* It also splits EPA section into its own
column rather than sharing the screen's merged "Section / jurisdiction" cell,
because Type I/II/III/Universal are different **equipment** under 40 CFR 82.161,
not ranks, and a spreadsheet filtered on "Universal" must not also match a
jurisdiction spelled the same way.

**And the export path was hardened platform-wide in the same window.**
`885fd0b9` fixed CSV formula injection in **53 places across 13 files** — *"a
customer name beginning with `=` executed as a formula in whoever opened the
export"* — and `mechCsvCell()` at `:1919` is this app's copy of the guard, with
the reasoning in `api/_lib/csv-cell.js`.

## 6. Limits

- **Markers are a floor, never a ceiling**, and three of them lied in the
  *favourable* direction this pass: `Manual J` 4→17 is a disclosure, `permit`
  0→4 is a doc-type list plus a disclaimer, `COI` 0→4 is a different object from
  the row it looks like. Each was hand-read. **A count that moves is a triage
  signal; the hit is the evidence.**
- **§§1–5 and §7 were not reconciled and cannot be** — competitor behaviour,
  user complaints and trade-body structure are not properties of this codebase.
  They inherit the 08-21 report's own standing, including its stated limit that
  search access was US-mediated and several claims are vendor-marketing grade.
- **Only the two regulations already re-verified on 2026-09-17 are current.**
  The rest of §4's worldwide licensing content was not re-checked here.
  **CARB was found in the CODE, not researched** — no primary-source pass was run
  on 17 CCR 95380 in this triage, and §2's threshold and floor are as the app
  states them.
- **No live check.** Every verdict is against the repository at `8e112b7b`, not
  the deployed app.
- **No code was written and no app file was touched.**

Six commits touched this app in the nine days between the 09-17 pass and this
one, and two of them moved rows that pass recorded as settled. **Nine days is
therefore a measured upper bound on how long this table stays true** — re-derive
