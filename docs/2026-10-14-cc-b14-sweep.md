## 3. A REAL DEFECT FOUND BY WAITING, NOT BY READING — `tools/run_all_tests.py`

**`acquire_lock()` will delete a LIVE run's lock after 15 minutes.** Measured
while waiting for the sweep:

```
lock pid 25196, age 16.1 min, LOCK_MAX_AGE 15.0 min
holder: ALIVE
past reclaim threshold: True
```

The reclaim is **age-only**:

```python
if age < LOCK_MAX_AGE:
    return False
os.remove(LOCK)               # abandoned by a killed run
```

The comment says *"abandoned by a killed run"* and the code cannot tell an
abandoned run from a slow one. **A normal full sweep on this clone takes longer
than the threshold that declares it dead**, so a second run started at minute
16 removes the first run's lock and proceeds — which is exactly the corruption
the lock exists to prevent, described in the tool's own skip message:

> *Two at once corrupt each other — a probe that mutates a tracked file
> snapshots whatever is on disk when it starts, so the second run adopts the
> first's mutation as its 'original' and restores that. Nothing was verified.*

**It is not fixed in b14** — found at the wrap-up point, and a lock change
needs a failing-first arm and an ablation, not a quick edit. **Parked with the
fix already decided**, because the platform has solved this exact question
once:

**The fix is the 2026-09-23 correction to `sairn_claim.is_active()`, applied
one domain over:** *the honest question is not how old the lock is but whether
the process that took it is still running.* The lock file **already records the
pid**. So:

1. reclaim only when the recorded pid is **GONE**;
2. use age **only** when liveness cannot be determined;
3. import the recycled-pid defence from `session_lock_check.owner_state()`
   rather than writing a second copy — `sairn_status.py` already imports it for
   the same reason, and two copies of that defence is two answers to the one
   thing it must not get wrong;
4. **raise nothing.** Raising `LOCK_MAX_AGE` makes both halves worse, which is
   the argument `is_active()` already records: a bigger number holds a crashed
   run's lock longer while still eventually stealing a live one's.

**The arm that must fail first:** a lock file naming a **live** pid with an
mtime older than `LOCK_MAX_AGE` must NOT be reclaimed; a lock naming a **dead**
pid must be; and an **unparseable** lock falls back to age, because an
unreadable holder is a could-not-tell and not a free pass.
