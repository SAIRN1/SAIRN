## ITEM 13 — TWO METHODOLOGY RULES, WITH MY OWN EVIDENCE, ROUTED

### (a) Before calling any gate or tool wrong or stale, re-measure in a clean detached worktree at `origin/main` with your untracked files excluded

**My evidence, 2026-10-06.** The push gate refused a commit saying three
generated documents no longer matched their sources, and *"this push is what
changed the answer"*. I unstaged my new file, the block survived, and I
concluded **the documents were already stale at HEAD and the gate's
attribution was wrong** — the same false-attribution class I had reported
against three other tools that day. One commit from writing it down.

Then I **moved the untracked file out of the tree** and re-measured:

```
tooling_inventory.py --check    EXIT 0
master_plan.py       --check    EXIT 0
traceability_matrix.py --check  EXIT 0
```

**THE GATE WAS RIGHT AND I WAS WRONG.** The generators read the working TREE,
not the index, so an **untracked** file was changing their answer while
`git status` showed it as harmless. **Unstaging is not excluding.**

### (b) A load-and-list smoke test is never evidence of no behaviour change

**My evidence, 2026-10-05/06.** I recommended `firebase-admin@14.5.0` on *"0
of 248 suites changed verdict"* plus a check that loaded
`api/_lib/firebase-admin.js` and listed its exports. It passed under both
versions, and I wrote that the wrapper *"LOADS under 14.5.0 and exports all
three functions"*. **True, and it was module resolution, not a token.**

An arm that drives the real path found it in one run:


**`initializeApp` surviving is the whole mechanism.** A smoke test that only
imports and enumerates is satisfied by one surviving symbol.
