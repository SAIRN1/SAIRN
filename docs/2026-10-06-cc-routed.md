## 7. `docs/METHODOLOGY.md` — three conventions (fourth)

Each was paid for this batch.

**(a) A BRIEF'S PREMISES ARE VERIFIED BEFORE EXECUTION, WITH A PER-PREMISE RESULT
RECORDED.** Not "read the brief carefully" — *write down, premise by premise, what
you found at HEAD before doing any of it.* Measured: of the eight premises in this
batch's brief, **three were wrong about WHERE or WHETHER and one item was already
done.** The scratchpad a prior session was said to hold was empty; the pre-commit
fix was already committed; a test arm said to be missing was present and provable
by mutation; a tool said to exit 2 exited 2 for a different reason than stated. A
brief is the least trustworthy document in the repository precisely because it is
the most recent, and when it is *your own prior report* it carries your own blind
spots forward with full confidence.

**(b) A HOOK OR CHECKER LEG THAT RETURNS SUCCESS ON A FAILED LEG IS A SILENT SKIP
AND MUST FAIL LOUD.** The shape is `if rc != 0: return 0` — and the problem is not
the early return, it is that **nothing downstream can tell it from "nothing to
report"**. Three instances in this batch alone: the `--post` observer returned
silently when `rev-list` failed; `hover_routing_gap_check` returns zero gaps when
`routable` is renamed or a `ts` fails to parse; `mutation_anchor_check` reported
COULD NOT READ for five arms and exited 2 on a convention nobody had written down.
The rule: **every leg reports its own outcome and NAMES what it could not read.
Only a total blackout — no leg readable at all — is silence,** because then there
is no observation to offer.

**(c) WHEN ONE CHECKER PRODUCES THREE OR MORE FALSE-POSITIVE CLASSES FROM ITS OWN
AUTHOR'S COMMANDS, STOP PATCHING AND REVIEW THE DESIGN.** `exit_status_attributable`
reached **five** classes, and the fifth revealed that the defect was never in the
subject half at all — the same raw-text split was wrong in the *attribution* half
for every command carrying a quoted separator. Four patches had each fixed a
symptom. The design question — *should this read text or tokens?* — was only asked
at five, and asking it produced a better answer than another patch: a tokenised
parse agreed on all 23 arms and then **refused** an unmatched double quote the
regex handles, so it became a **cross-check** rather than a replacement, and every
arm is now decided twice by implementations sharing no code.

**The threshold is three because that is where a pattern becomes cheaper to fix
than to keep paying for**, and the signal is specifically *the author's own
commands* — a checker that fires on its author is firing on the usage it was
designed around.

### Rule A — a measurement whose CONTROL fails the same way as the test is DISCARDED, not reported

**A control only licenses a conclusion when it can FAIL DIFFERENTLY from the
test.** If one defect takes both arms down together, the comparison carries no
information, and the result is not a weak result — it is **no result**. It is
discarded, and the discarding is reported.

**PAID FOR 2026-10-06, 26 runs.** I measured where a registry refusal lands
across 13 importers, before and after a change, by wrapping each run in
`timeout 120`. Inside `nohup bash -c` on this machine `timeout` resolves to
**Windows `timeout.exe`**, which rejects those arguments. All 26 invocations
answered `ERROR: Invalid syntax` — **the control arm identically with the test
arm.** The exit codes were real, uniform and meaningless.

**THE TRAP IS THAT IT LOOKED LIKE A RESULT.** Thirteen rows, two arms, a status
per cell, every number present. A missing control is conspicuous; a control that
ran and died of the same cause is not. Had I reported the uniform exit 1 as
"unchanged before and after", that sentence would have been true of the numbers
and false about the world.

**THE TEST, as a question to ask before quoting any paired measurement:** *name
one defect that would make the control and the test agree.* If one exists and
has not been excluded, the measurement is not yet evidence. **And prefer a
control that is a different KIND of thing**, not the same command with one flag
changed — a shared wrapper is a shared single point of failure, which is item 6
(independent replication needs a structurally different method) arriving one
level down, in the harness rather than in the method.

**The repair was not a better wrapper, it was no wrapper:** `capture_exit.py`
already records the real status, and a cap enforced by the process that waited
on the child cannot be shadowed by a PATH lookup.

### Rule B — a one-direction reassurance is a defect; drive BOTH cases before writing it down

**A message that explains what is NOT wrong must be true in every state that can
reach it.** Reassurance is asserted far more casually than a finding is, and it
is read with the same trust.

**PAID FOR 2026-10-06, TWICE IN ONE BATCH, AND THE SECOND TIME WAS THE FIX FOR
THE FIRST.**

1. `tools/checker_selftest_check.py` exited 2 with *"COULD NOT READ
   `tools/report_only_checks.py`, **or** its REGISTRY is empty"* — a disjunction
   printed without knowing which disjunct held. Driven: the file read fine and
   the registry held 76 entries. **Neither was true.** The exit code was right
   the whole time; the explanation was false.
2. Fixing it, I wrote *"the file was NOT found to be unreadable and the registry
   was NOT found to be empty"* — **true of the raise case and false of the
   module-absent case**, where the module genuinely is absent. Caught only by
   driving arm C as well as arm A. Deleted, and the deletion is commented in
   place.

**THE PROCEDURE:** for every clause of the form *"X is not the problem"*,
enumerate the states that reach that line and drive **each** one. If a clause
cannot be made true in all of them, delete the clause — the named exception is
already the evidence, and an unqualified cause line beats a qualified one that is
sometimes wrong. The repaired message asserts nothing beyond the exception it
caught.

**AND THE STRUCTURAL FIX IS CHEAPER THAN THE DISCIPLINE:** carry the real cause
out of the `except` instead of paraphrasing it. A `str(e)` cannot be false about
its own exception, whereas any sentence written *about* it can.

### What is and is not a finding here

**FIFTEEN OF THE SEVENTEEN ARE GENERATORS AND WRITING IS THEIR JOB.** The
`gen_*` family and `sairn_build_load_gates.py` exist to emit `sql/`; a
generator that wrote nothing would be the defect. `tools/bare_run_writers.py`
already records 21 owner-intended bare-run writers with the path each one
writes, which is the right shape for this and covers most of these.

**THE TWO WORTH A SECOND LOOK ARE THE TWO THAT EXITED 2 WHILE WRITING:**
`audit_checkpoint_status.py` and `cron_liveness_check.py` both left a document
behind **and** reported COULD NOT RUN. A generated status document written by a
run that could not complete is a document whose contents nobody has established
— and it is the kind a reader treats as current. **I am not calling it a defect:
exit 2 may be the correct answer to a genuinely unanswerable question and the
file may be an honest "could not tell" page.** Neither is in my claim, and the
cause tag for both is **phase: generation, sub-phase: outcome-vs-artefact
agreement, specific cause: unknown — I did not read either generator.**

### Blind spots, printed on every run of this sweep rather than argued here

* a tool that writes **outside** the repo — `~/SAIRN-SESSION-LOCKS`, `%TEMP%` —
  is invisible to `git status` and is **not** counted as a writer;
* a tool that writes only on a code path this invocation did not reach is
  counted as clean;
* the 60s cap means a **TIMEOUT row has no write verdict at all**, so the 17 is
  a floor rather than a total.

**AND A COSMETIC DEFECT IN MY OWN SWEEP, stated because the table above shows
it:** the path column strips a fixed three characters from `git status
--porcelain`, which is right for `?? ` and `M  ` and wrong for one of the
rename/copy forms — hence `ocs/AUDIT-CHECKPOINT-STATUS.md` in the raw output.
The tool names and the verdicts are unaffected; the paths in the table above are
corrected by hand.
