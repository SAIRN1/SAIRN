## 1. CONCEPT, STATED BEFORE THE CODE

Classify a refused push by who said it:

- **Transient, so retry.** Git's own remote-race and transport rejections:
  fetch first, non-fast-forward, cannot lock ref, host and network failures.
- **Deterministic for that tip, so stop.** Anything the pre-push gate printed:
  `Blocked:`, "blocked by .githooks/pre-push", `ESCALATING:`.
- **The one exception: a gate refusal naming a GENERATED document.** The loop
  can fix that itself, so it retries once, and only if the regenerate actually
  folded.
- **Unclassified text, so stop.** When a retry costs an escalation and a stop
  only costs a re-run, the unknown case goes to stop.

## 2. THE FIX: `tools/push_retry.py`

The b31 bug was in my inline loop. **The shared tool had the same shape:**
`cmd_loop` printed the refusal and went round again whatever it said.

The change:

- `classify_refusal()` and its two marker lists are added.
- After a refusal, the loop now acts on the class:
  - **transient:** continue;
  - **generated:** regenerate and fold, and stop if the fold did not happen;
  - **anything else:** stop with **exit 5**.
- The docstring CLI names exit 5.
- Gate text is matched **before** transient text, because every gate refusal
  also ends in git's generic "failed to push some refs".

**Proven by driving `cmd_loop` with `git` stubbed, counting pushes, over 4
attempts:**

| version | Tier A gate refusal | fetch-first race |
|---|---|---|
| before (HEAD) | **4 pushes**, rc 1 | 4 pushes, rc 1 |
| after | **1 push**, rc 5 | 4 pushes, rc 1 |

**Selftest: 11 new arms, all passing.**

- Nine classify real texts copied from the b31 refusals: Tier A,
  could-not-run (WinError 206), ESCALATING, a generated document, fetch first,
  lock ref, network, unknown and empty, and gate text winning over the generic
  git line.
- Two drive the loop itself: it pushes **once** on a gate refusal, and as a
  control it still retries a race.

All pre-existing arms still pass.
