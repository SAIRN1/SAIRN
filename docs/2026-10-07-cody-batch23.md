## 11 — METHOD IMPROVEMENT: a redirection that fails must not leave the program pointed at production

Paid for inside this batch, by §3c.

**BEFORE.** To replay a one-shot script against a sandbox copy I rewrote its
target path with `sed` and ran it:

```sh
sed "s|P = r'C:\\Users\\marsh\\.claude\\settings.json'|P = r'$SP/i3/replay_input.json'|" \
    "$OLD/merge.py" > "$SP/i3/merge_replay.py"
python "$SP/i3/merge_replay.py"
```

The pattern did not match (backslashes), **`sed` exited 0**, and the script's
path stayed as written — so the replay ran against the live
`~/.claude/settings.json`. Two independent failures lined up: the substitution
was silent, and the *default* on failure was production.

**AFTER.** The substitution asserts it happened, and says so:

```python
assert src.count(old) == 1, 'anchor count %d -- NOT 1, refusing' % src.count(old)
io.open(dst, 'w', ...).write(src.replace(old, new))
print('anchor replaced exactly once')
```

plus `grep -n "^P = "` on the result before running it, which printed the
sandbox path. The second run touched nothing outside the scratchpad —
confirmed: `~/.claude/settings.json` mtime unchanged by it.

**The rule, and it is NOT just "use a uniqueness guard".** The platform already
has the uniqueness-guard convention (`count(anchor) != 1`) and I did not apply
it — that half is reinforcement. The half that is new is about **what the
failure falls back to**: *when a program is being redirected at a sandbox, a
failed redirection must fail, not inherit the real target.* The structural form
is to take the path as a **required argument with no default**, so a redirection
that does not happen is an immediate crash rather than a write to production.
A uniqueness guard catches the mistake; a required argument makes the mistake
unable to reach production at all.

**Routed, not written into either convention file** — `docs/METHODOLOGY.md` and
`docs/2026-09-13-cross-domain-disciplines.md` are both declared by fourth.
