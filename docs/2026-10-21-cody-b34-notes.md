## 2. The ~50 heuristic sites — proved per RESOURCE, not by proximity

CONCEPT: proximity is not pairing. A read projection is inert only against the
`storedBlob()` strip lists of **the same resource** (pooled over the read and write
blocks that name it), so the tool brace-matches each `if (resource === 'X')` block
and compares there. `docs/b33-sweep/pair_by_resource.py`:

- **PAIRED (44)** — every key is in the strip list of **every** `storedBlob()` call
  for that resource (not the pooled union), **and** no block for the resource stores
  the raw payload as the blob.
- **THE RAW-WRITE CHECK WAS BROKEN ON ITS FIRST VERSION AND THE PUSH GATE CAUGHT IT.** The regex was generated through a non-raw string, so each `\b` became a 0x08 backspace byte (and `\s` was doubled) and it could never match: the first "0 raw writes" meant nothing. The control-byte gate refused the push; repaired, checked against six strings, and re-run: **still 0 raw-payload writes** in the 44 paired resources' blocks.
- **NO-STRIP (17) + GENERIC (2)** — no `storedBlob()` for that resource (allowlisted
  or raw) → **read by hand**, below.
- **Positive control:** run against the b32 tip, it reports the live `bld_draws`
  sites as NO-STRIP and the two live `alf_*` rule sites as GENERIC — i.e. **none of
  the four defects fixed in b33 would have been classified clean**.

### What this still does not prove

- A write path that bypasses `sd-data.js` and `sd-sub-data.js` is covered only by
  the cross-file grep above (`rest('<resource>…')` outside those two files).
- `*.html` is not swept.
