### The one gap that is shared, and what b22 did about it

**`api/sd-data.js:16594` calls `legRoles.decide(resource, role, action)` with
THREE arguments. `decide()` takes FIVE.** So `grants` and `home` are
`undefined` on every real request, every apprentice gets the empty F3 default,
every driver gets the default F2 setting, and **neither config can have any
effect in production regardless of what a home stores.**

That has been recorded in prose in the b19, b20 and b21 handoffs and in a
comment at the call site. **A paragraph in a handoff is not a mechanism.**

**b22's contribution is to make it an arm.** `D1` asserts the arity of the live
call site and **fails the day somebody wires it** — which is the intended
outcome, and the arm's own failure message says so:

> *A FAILURE HERE IS GOOD NEWS: it means the wiring landed. Do not silence it —
> delete this arm and promote the F2/F3 arms from module-level to
> handler-level.*

An arm whose failure reads as a regression gets silenced instead of actioned,
so it says which it is. `D2` asserts `leg_settings` appears in **no code** in
that file (only in the handler's own comment recording the gap) and fails if
the comment is ever deleted — losing the record is worse than the gap. `D3` is
the negative control: `decide.length === 5`, and passing the two dropped
arguments **demonstrably changes the answer**, so the gap is not harmless and
the arm is worth asserting.
