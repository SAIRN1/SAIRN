## 2. ROOT CAUSE: WHY TEN WEEKS PRODUCED NO VISIBLE BREAKAGE

**The error is swallowed, deliberately, at two layers. A different table is
NOT being hit.** Whether real customers ever reached these paths **cannot be
determined from the repo**, and is not claimed either way.

**Layer 1, the API.** A READ against a missing table returns
**HTTP 200 `{ok:true, data:[], provisioned:false}`**:

- `api/sd-data.js` `unreadableNotEmpty`, `:20404-20423`, passes 404 and
  PGRST205 through as provisioned:false;
- the same shape appears in each bespoke branch (`api/org-intel.js:136` and
  others).

This is by design, so that a missing table can be told apart from an empty
one. **Proven live, not read:** signed-in reads on RF-AUDIT-2026
(`rf_job_warranties`, `rf_warranty_tiers`), SEN-PINNACLE-2026
(`sen_payer_contracts`) and DNT-PINNACLE-2026 (`dnt_gfe`) all came back
MISSING through the real deployed endpoint.

**Layer 2, the clients.** They ignore `provisioned:false` almost everywhere:

- `sdData` (`stonedesk.html:30382`) returns only `j.data`;
- `senHydrate*`, `sfServerWinsMerge` and the dental read sync at
  `sairndental.html:6506` merge `[]` additively, so nothing changes;
- every write saves to **localStorage first**, then the server answers 503
  and the user gets a toast such as *"Saved on this device only"*.

On the device that entered the data, the app looks exactly right. **The data
simply never leaves that browser.** Nothing is lost visibly; it is lost
invisibly to every other workstation, to backup, and to audit.

**Where it is NOT silent, it fails CLOSED:**

- The SAIRNcare witness gate (`api/sairncare-witness.js:428-432`) refuses every
  `alf_mar` `entry_type='count'` write with 503 NOT_PROVISIONED while
  `sairncare_witness_tokens` is missing. **That is a live, visible refusal
  today**, for controlled-substance counts only.
- SAIRNvet's equivalent gate refuses too. `sairnvet.html` sends no witness
  token at all, so it gets 403 whether or not the tables exist.

**Urgency, as this changes it:**

1. **`dnt_gfe` is highest.** It is a federal (45 CFR 149.610) record whose
   issued date currently exists only in one browser.
2. **The SAIRNcare witness tables** are blocking a function outright.
3. **Senior authorisations and payer contracts** are a billing-correctness
   risk on the device that holds them.
4. The rest is invisible data loss rather than wrong output.

**(c)** All three `rCredentials` branches overwrite every tile and the badge,

**(d) RE-DECIDED from the rule rather than the label.** "Not later than" makes
