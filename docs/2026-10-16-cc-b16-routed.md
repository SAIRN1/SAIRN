## → Michael, one decision

### M1. The documented route to a scoped gate skip does not work, and it cost four pushes to find out

`SAIRN_SKIP=<gate> SAIRN_SKIP_WHY="..." git push ...` is the form the push
gate's own refusal recommends, and it is **derived from `gate_skip` rather
than hardcoded**, so it is not a stale copy. It still never grants anything:

* nothing in the push path calls `gate_skip.grant()`;
* `_scoped_skip()` in `tools/sairn_push_gate_hook.py` only honours a record
  file that **already exists**;
* the only thing that writes one is running `tools/gate_skip.py` itself with
  those variables set.

So the environment variables in front of `git push` are read by nobody and the
scoped form silently appears broken — which is exactly the pressure toward the
blanket form that **80 of the 94 `docs/BYPASS-LOG.jsonl` rows already are**,
taken because it was the only thing available.

The working sequence, measured:

    SAIRN_SKIP=tier-a SAIRN_SKIP_WHY="<reason>" python tools/gate_skip.py   # grants, 30 min
    git push origin main                                                    # honours it

**The decision is which one to keep**, and it is not cc's: either the push gate
grants from the environment on the spot (one call, and the reason is validated
at the same moment), or the hint stops recommending a form that does nothing
and names the two-step instead. cc has not changed either, because changing
the hint to match a broken route and changing the route to match the hint are
opposite answers to the same question.
