## The two concepts, before the code

**Item 1.** *The tier checker's registry scan must skip a file because that

## Item 1 — the skip is now a property each module declares

### What was wrong, and it failed open in both directions

```python
if app in ('index', 'shared'):     # <-- half of this list was wrong
    continue
```

`index.js` belongs out of the scan — it is the merger. `shared.js` does not:
it is a registry with seven real resources, including `employees`, which is
Tier A on both axes. So the completeness arm reported **clean** over all seven
for as long as they had no row, **and** rejected the rows once written. The
register could not be made correct while the skip existed.

### The property, and why this shape

**A registry declares `app:` in its own `module.exports`. The merger declares
none and `require()`s its siblings instead.** Measured over all 20 files in
`api/_resources/` before writing anything: exactly one lacks `app:`, and it is
`index.js`. The distinction is structural rather than nominal.

**Michael's decision was a property, not a name list, and the reason holds:** a
tuple goes stale silently the next time a file is added; a property cannot,
because the answer travels with the file.

**Why not an explicit `__notARegistry` flag,** which would be clearer still:
it needs an edit inside `api/`, which is hank's this batch. Reading a
declaration the modules *already make* needs no edit anywhere and no
coordination. The case for an explicit flag is a merger that *does* declare
`app:` — and that case is asserted as an arm so it cannot be a surprise.

**The declared name is also checked against the filename.** A disagreement is
reported as a shape error, never resolved by preference: two answers to one
question, and silently picking either is how a resource gets filed under an app
that does not own it.

The 6 that remain are **not mine and not fourth's b35 work**: four

All sit in `docs/CRITICALITY-TIERS.md`, which fourth holds — routed.

### Arms

Criteria lock **6/6 → 12/12**, and the printed count is now **derived and
returned** rather than `len(FIXTURE_CASES)`: adding six arms made the old

- **Arm:** a module declaring `app:` is a registry; all four root shapes.

2. **`routes` stays its own registry file.** With the skip gone, `shared.js`

**Verdict: sound on confidentiality as designed, with one HIGH finding that

**FINDING 1, HIGH — `rt_stops.license_hash` is a second copy of the tenancy key
and nothing ties it to its route's.** `rt_stops` carries both
`license_hash text not null` and `route_id references rt_routes(id)`, and the
schema has **no composite foreign key, no check and no trigger** requiring the
two to agree. `idx_rtstops_license` exists so a reader can scope by that
column, so a stop written with licence A under a route of licence B is visible
in A's scope while belonging to B's itinerary — on a Tier A **confidentiality**
table whose content is a named person at a street address on a date.

Measured, not inferred: **`api/_lib/routes.js` never reads or writes
`license_hash` at all** — the string does not appear in the file — and neither
consumer sends one. So the only thing that can get this right is the unlanded
handler, and nothing will catch it if it does not. **The deciding test is
written down before it can be run:** does the handler derive
`rt_stops.license_hash` from the **route row** it is attaching to, or from the
request? A composite FK over a `unique(id, license_hash)` parent would make the
invariant structural; the schema is fourth's and the handler is cody's, so this
names it rather than changing it.

**FINDING 2, MODERATE — Tier A addresses leave the platform and the
confidentiality argument does not say so.** `driveMatrix` POSTs every stop
address verbatim to `routes.googleapis.com` as both origins and destinations.
The key handling is right and kept right for a stated reason; `X-Goog-FieldMask`
limits what comes **back**. Neither limits what goes **out**, and there is no
ceiling on stop count — `stops.length < 2` is a floor and nothing caps it. Not
a defect in the code as written: a drive-time optimiser cannot compute drive
times without sending addresses somewhere. What is missing is the **disclosure
and a stated bound**.

**FINDING 3, CLOSED — fourth's own `sd_field_stops` question is already
resolved and not by analogy.** b35 re-read `fmSaveStop()` at
`stonedesk.html:12879`, found `person` defaulted from `currentUser.name` plus a
free-text customer name, found it in `SD_SYNCED` so it leaves the device, and

## Item 4 — the red-flag threshold, per population

### A bare `RED_AT = 80` would have been the wrong edit

`tools/sairn_status_line.py` is wired as `statusLine` in
`~/.claude/settings.json`, which is **user-level**: one entry renders the line
in all six agent folders. So the single constant is not a per-agent setting
that happens to be shared — **it is the only setting there is**, and raising it
would have moved hover's and hover2's threshold at the same time, which the
instruction forbids.

```python
RED_AT_DEFAULT = 70     # Michael's b8 threshold. UNCHANGED.
RED_AT_BUILD   = 80     # Michael's b24 threshold, build agents only.
```

Keyed on `agent_name()`, which reads the per-clone marker inside `.git/` rather
than the folder name — hover finding #258 applied to a number instead of a name.

**An unknown agent gets the DEFAULT, not the higher one.** An unprovisioned
clone or a worktree keeps 70: if the identity is not established, the safer
threshold is the one that warns **earlier**. Raising the bar for a session
nobody can name is the direction that costs a batch.

**The wrap-up trigger is untouched** — it stays at the measured figure from
`context_verify`, and nothing here reads or writes it.

### Arms

Criteria lock **26/26 → 38/38**.

- **Arm:** each of the four build agents resolves to 80.
- **Negative control:** `hover` and `hover2` resolve to **70, unchanged** —
  without this the arm would pass on a change that simply raised the number for
  everybody, which is the edit the instruction forbids. Plus `''` and a
  look-alike name both resolving to 70.
- **Driven end to end** on a provisioned temporary clone, both sides of the
  boundary: 75% is **not** red, 80% **is**, and the agent is named from its
  marker. A clone that cannot be made prints COULD NOT RUN rather than being
  silently absent.
- **Ablation on the identity alone:** the identical 75% transcript under
  `hover` is **still red**. Same file, same model, same window — only the
  population differs, so the threshold cannot have been raised platform-wide.
- **Ablation on the value:** setting `RED_AT_BUILD` back to 70 fails **5 arms**
  including the driven one. 38 → 33.

## Item 5 — the path manifest and the pre-push scope check

`docs/sairn-path-manifest.json` (data) + `tools/sairn_path_manifest.py`
(mechanism) + CHECK 5d in the existing pre-push hook, gate id **`path-scope`**,
`WIRED` in `gate_skip.py --gates` (11 skippable). **No `settings.json` entry
and no other hook mechanism**, as instructed.

The owner split is Michael's, verbatim: `api/` hank, `tests/` cody, `tools/` cc,
`docs/` fourth, `.html` fourth. Auditor paths are denied to **all four**, and
that test runs **first** — before any allowance — because an allowance that
could reach into the auditor's scope would be the boundary failing in the one
direction the separation exists to stop.

### THE SPLIT ALONE WOULD REFUSE THE PLATFORM'S NORMAL OPERATION

Measured over 2026-10-18..19 **before** designing anything: all four agents
wrote `docs/` (hank 8, cc 18, cody 3, fourth 13 commits), all four wrote
`.claude/claims/` (8/13/11/16), and every batch's handoff, report and digest
sits at the repository root. A hook that refuses every agent's own batch
artefacts and its own claim is a hook switched off within the hour.

So two **narrow** allowance classes sit on top of the split, both named in the
manifest rather than hidden in code:

- **SELF-NAMED** — a path carrying the *pushing* agent's own session name.
  `SAIRN-handoff-cc-*` is cc's and nobody else's; cc pushing hank's handoff is
  not allowed by it.
- **SHARED LEDGERS** — an explicit **path list, never a prefix**, of files whose
  declared merge policy is union-by-identity. A prefix would re-open all of
  `docs/` and the split would mean nothing.

### What it would have said over 400 commits

| population | paths | REFUSED |
|---|---:|---:|
| cc | 66 | **0** |
| fourth | 60 | 2 (`tools/branch_census.py`, `tools/tooling_inventory.py`) |
| hank | 61 | 2 (`tools/index_duplicate_check.py`, `tools/sairn_push_gate_hook.py`) |
| cody | 50 | 14 |

**And this table's attribution is a proxy, which limits it.** The population
comes from the first build-agent name in the **commit subject**, so a subject
naming two agents is attributed to the wrong one — measured on this corpus, a
`batch-manifest-fourth-b31.json` path lands under `cody`. **The live check does
not use this proxy at all**; it reads the pushing clone's own marker. Use the
table for the shape of the answer, never as a count of real violations.

### DECISION-NEEDED: cody and `.html`

cody pushed `.html` repeatedly under Michael's own explicit assignment
(sairnroofing, sairnscape) while the split gives `.html` to fourth. That is a
real conflict between the split and standing practice, not a gap in the
manifest. `assigned_overrides` is the declared route and it is **empty**, so
**cody pushing `.html` is refused today**. Flagged, not decided: either declare
the override, or the assignment moves.

### Arms

Criteria lock **31/31**, all four shapes Michael named:

- **In-scope passes** — each population on its own area, including the `.html`
  glob rather than a prefix.
- **Out-of-scope rejected** — and the refusal **names the owner and the route**
  rather than just saying no.
- **A mixed push is rejected whole** — two in-scope paths do not license a
  third, and the in-scope paths are still classified so the reader sees the
  whole push.
- **Ablation on the manifest entry** — removing hank's `api/` ownership makes
  cc pushing `api/sd-data.js` no longer FOREIGN, so that entry is what was
  refusing it and nothing else; plus a control proving the ablation moved one
  thing, and a second ablation on the auditor list.
- Fails closed on its own inputs: missing, malformed and wrong-shaped manifests
  are each **exit 2 COULD NOT RUN**, and an unestablished identity is too —
  "is this path mine" has no answer when "who am I" has none.

### A defect of mine, caught by the fixtures within the minute

`_under()` normalised with `path.lstrip('./')`. **`str.lstrip` takes a set of
characters, not a prefix**, so `.claude/claims/cc.json` became
`claims/cc.json` — the leading dot of every dot-directory eaten, and
`.claude/` and `.githooks/` stopped matching entirely. Four arms went UNOWNED
**including the auditor boundary**, which is the one whose silent failure would
have mattered most. Replaced with `_norm()`.

And a second: `--history` passed `--format=%%H%%x1f%%s` to git, which received
it literally, so no line contained the separator, every commit's population
read as unknown, and the report printed an **empty table under a confident
heading**. Both are written into the code where they happened.
