**Confirmed, and confirmed structurally rather than by repetition:** `run()`
called `proc.wait()` with no timeout argument at all, so there was no code path

runs the live ceiling would have killed** — and a killed `async` hook reports

### The fix, shaped by cc's own Rule A

*"The repair was not a better wrapper, it was no wrapper — a cap enforced by the
process that waited on the child cannot be shadowed by a PATH lookup."* Her
26-run measurement died because `timeout 120` resolved to Windows `timeout.exe`
and **failed the control and the test identically**. So the cap lives in the
process that already waits:

- `--bound SECONDS` / `run(..., bound=)`, **optional**.
- On expiry: terminate, then kill, then write
  **`COULD_NOT_RUN TIMEOUT_<n>s`** — *not* an exit code, because a killed run
  produced no verdict. Returns `None`; `--read` exits 2.
- **Backward compatible by construction**: `bound=None` takes the old path.
- Stated limit: it kills the **child**. A grandchild can outlive the kill, so
  `TIMEOUT` means "the child did not finish in time", not "nothing is running".


## ITEM 11 — METHODOLOGY

### THE RULE, from a real catch of my own, routed and NOT self-promoted

> **A bound measured against the tool's INPUT is not a bound on the tool's
> SUBJECT. Measure what the bounded call actually receives.**
>
> Before setting any timeout at 2x a measurement, identify the exact artifact
> the bounded call is handed — a transform of a file, a generated fixture, a
> worst-case payload — and measure **that**. The thing you happen to have on
> disk is a convenience sample.
>
> **Paid for 2026-10-07.** I replaced `metamorphic_check.py`'s unmeasured 120s
> bound with 40s, derived honestly as 2 × the 18.24s worst case of six checkers
> against `stonedesk.html`. The bound then fired on **three runs out of three**.
> A metamorphic check runs each checker against the file **and each TRANSFORM of
> it**; `t_duplicate` doubles the file, so the real subject is 5.51MB, and
> `duplicate_global_check.py` goes **0.82s → 71.54s** on that 2x input — **87x**,
> superlinear in duplicate ids. **The correct bound is 145s, which is HIGHER than
> the 120 I replaced.** My tightening broke a working tool.
>
> **The test to apply:** name the exact bytes the bounded call receives on its
> worst invocation. If that is not the artifact you timed, you have not measured
> the bound.
