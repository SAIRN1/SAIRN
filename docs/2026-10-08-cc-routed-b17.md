## 1. How the sweep was run, and why that matters more than the table

**Every check was run ALONE, and its exit code was captured into its own file
on the line after it ran** — never read off the end of a pipe, an `&&` chain or
a loop. The harness is four lines:

```sh
one() {
  name="$1"; shift
  timeout 600 "$@" > "$S/$name.out" 2>&1
  echo "$?" > "$S/$name.exit"            # captured IMMEDIATELY, nothing between
  printf '%-40s exit %s\n' "$name" "$(cat "$S/$name.exit")"
}
```

This is not ceremony. Three times in this session the `exit_status_attributable`
hook warned me that a command I had written would hand back `head`'s or `git`'s
status rather than the tool's, and on 2026-10-04 that exact misreading put a
false *"EXITS 2 (COULD NOT RUN)"* accusation against a working checker into a
standing document. **No exit code in this file came from a chain.**

`timeout 600` is also load-bearing and cost me a wrong reading once in this
batch: `tools/cross_tenant_isolation_scope.py` was killed at a 120s ceiling on
its first attempt. **A kill at a ceiling is not a result about the tool** and is
reported below as what it was, not as a failure.

## 3. The sweep's actual value: it found a defect I had already reported green

**`python tools/tool_owner_map.py --check` exited 0 at `7b82997b` and exited 1
three commits later.** That is the whole case for re-running a check at the HEAD
you are reporting from rather than citing the run that made you happy.

The diff was one row. `tools/va_rule_currency.py`'s `last_commit` had moved from
`1ae447cf0b5e` to `7b82997b0de7` — because `7b82997b` is the commit in which I
edited that file. The map was right and the check was right; **the field I had
added was wrong.** 614 files carry basis `UNRECORDED`, so `last_commit` turned
the map into a regenerate-after-every-commit obligation, and a check that goes
red for a benign reason is a check people learn to ignore.

Fixed at `d562e53f` by removing `last_commit` and keeping `first_commit`. The
basis is *nobody has recorded an owner*, so the only useful thing the row can
offer is a routing target, and that is whoever **introduced** the file — a sha
that does not move unless history is rewritten.

**Measured in an isolated worktree, with the ablation, because otherwise this is
a story rather than a cause:**

| state | `--check` |
|---|---|
| fixed tool, regenerated JSON, baseline | **exit 0** |
| then a commit touching an `UNRECORDED` file | **exit 0** ← the fix |
| `last_commit` restored, same commit | **exit 1** ← the cause |

The mutation asserted it applied (the anchor was counted before replacing, per
scrubber item 17) so the red is the field coming back, not an anchor that
silently missed.
