A BLANKET "STOP AT ANY HEADING" RULE WOULD HAVE BEEN WORSE, and this is why
the concept was written before the code. cody b23's CHANGED carries `ITEM 1 --`,
`ITEM 2 --`, `ITEM 3 --`, `A DEFECT RECORD WAS WRITTEN`; its NEXT carries
`WHOEVER TAKES THE NEXT SWEEP REPAIR`, `HANK --`, `CC --`. Every one is
blank-line-preceded, at column 0, upper case -- the same shape as hank's -- and
every one is genuinely part of the field a reader wants. Terminating there
would have cut cody's CHANGED to one paragraph and called it the whole field.

SO THE RULE IS SCOPED BY WHAT THE FIELD IS:

  CONTEXT is a FIGURE field. Its content is a few words, so a
  blank-line-preceded heading inside it is always the next section. It
  terminates there: hank's 4,673 characters became 3, `46%`.

  STATUS and NEXT are PROSE fields. They legitimately carry their author's
  headings, so they still end only at a known label or at end of file -- and
  when one contains such a heading the fields dict NAMES it. Live, cody's NEXT
  reports "carries 3 of the digest's own heading(s) (first: 'WHOEVER TAKES THE
  NEXT SWEEP REPAIR -- TAKE'); the field is NOT cut there". Same pattern as
  b18's tolerance note: a bound nobody can see is a bound that widens.

================================================================================
ITEM 2 -- THE PUBLISHER RACE
================================================================================

WHAT HAPPENED IN b18, measured: cc's clone published a corrected board at
08:34; FOURTH'S CLONE REPUBLISHED AT 08:55 with its own pre-fix copy of the
publisher, and the broken cells came back with no error anywhere. It resolved
itself when other clones pulled -- luck, not a mechanism.

THE DATA WAS NOT STALE. THE CODE WAS. Every clone renders from the same
registry outside git, so fourth's rows were as fresh as cc's: a
last-write-wins check on row timestamps would have let that publish through
unchanged. That is the measurement that decided the design, and it is the one
the dispatch's wording would have missed.

TWO COMPARISONS, in overwrite_refusal(), before a single byte is written:

  PUBLISHER REVISION. The board carries the revision of the publisher that
  wrote it -- published in the header on purpose, so the guard reads the BOARD
  rather than trusting its own copy. A clone on a LOWER revision refuses.
  Compared as a NUMERIC TUPLE: `2026-10-19.10` < `2026-10-19.9` as text, which
  would invert the guard the first time a serial reached two digits. Arm A34
  asserts both the correct comparison and the textual trap.

  ROW RECENCY. Per agent, the board's rendered `row written` stamp against what
  this process would render. A board showing a row NEWER than this clone can
  see means the registry read behind it is stale, so publishing would walk the
  board backwards. Arm A36.

REFUSE, NEVER MERGE. A merged rendering of six agents' state describes no
moment that ever existed. "Reject" is the branch of the decision that can be
made correct.

AND REFUSING DOES NOT BREAK THE CALLER. Publishing is a side effect of a status
or claim write; the write still succeeds and the board is reported NOT
PUBLISHED with its cause and the command that fixes it:

    BOARD NOT PUBLISHED -- this clone would have REVERTED a newer board.
      the board on the mount was written by publisher revision 2099-01-01.1
      and this clone is running 2026-10-19.1 ...
      Your status or claim write SUCCEEDED; only the Drive board was left
      alone.
      Fix: git pull --rebase origin main, then re-run any status command.

TWO CONTROLS, because a guard that refused everything would be worse than the
race: arm A35 proves an OLDER board and an ABSENT board both still publish, and
that publish() returns EXIT_CLEAN with the file written. Arm A33 proves the
refusal leaves the existing file BYTE-UNTOUCHED, not merely unreported.

THE LIMIT, in the source: a clone running a publisher older than revision
2026-10-19.1 neither writes the field nor reads it, so it cannot be stopped by
this. The guard protects every clone from this revision forward and the push is
what distributes it. A revert from a pre-revision clone stays possible until
each clone fetches.
