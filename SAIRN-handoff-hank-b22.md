> **FIX STATEMENT.** Every identifier interpolated into a PostgREST filter must

them, so an `&` **starts a new parameter**. A `command_id` of

`cmds[0].id` out of**.

### Item 3 — the forgeable pre-auth log line. **CLOSED.**

> **FIX STATEMENT.** The pre-auth log line must render `app_id` as a single safe
> token — validated against `KNOWN_APP_IDS`, otherwise sanitised, labelled and
> length-capped — so no request body can inject a forged log line.

It logged `body.app_id` on **every** call, **before** the allowlist check,
**including unauthenticated ones**. A newline wrote a second entry
indistinguishable from a real one, with an attacker-chosen `state=`.

**The forged `state=valid` is the point.** `auth_observe` exists *because*
`SAIRN_CLAUDE_AUTH_MODE` defaults to `observe` — the log **is** the evidence an
operator reads, and the entries it cannot be trusted on are exactly the ones
read during an incident.

**Three rules, each closing a different hole:** validate first; strip the whole
control class (**CR alone** forges a line on a CR-splitting reader, **ESC**
drives a terminal that renders the log, **U+2028/U+2029** are breaks to many
viewers); and **cap at 40, applied AFTER stripping**, so 5,000 newlines cannot
spend the budget and let a forgery through behind them.

**The value is sanitised, not dropped** — this file's own history is the
argument: SAIRNsenior's every AI call 400ed silently for weeks and was found
because a refusal **named** the unrecognised app_id.

**`api/b22-claude-logline.test.js` — 12 arms, 0 failed**, including **A2** over
the whole break-character class (a newline-only fix would pass A1 and leave CR,
ESC and NEL open) and **E1** asserting the sanitiser's regex carries **no
literal control byte**.

**E1 exists because I wrote that defect first — twice.** The first draft
embedded real control characters in the character class, and so did the test
file, which would have been **a checker carrying the defect it checks for**.
