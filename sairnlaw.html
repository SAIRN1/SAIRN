AI Assistant
Powered by Claude · Citation-grounded — never presents an unverified case citation or statute as fact
This assistant will never output a specific case citation, statute citation, or docket number in citable- reference format (e.g. "384 U.S. 436 (1966)") -- not even for a famous case, not even paired with a disclaimer. It can describe a case narratively (the holding, the parties, the era, the legal principle) but always directs you to Westlaw, Lexis, or the court's own site for the actual citation. It also has no access to this firm's real matters, deadlines, trust balances, or billing data -- it will say so and point you to the relevant panel rather than guess. Both are enforced by the system prompt below, not a UI label bolted onto unverified output.
Intake Memo Conflict Check Basics Deadline Reminder UTBMS Overview
Ask for drafting help or general legal-practice explanations. It cannot look up this firm's actual matters, deadlines, trust balances, or billing -- check those panels directly.

Trust Accounting (IOLTA)
Client funds, tracked completely separate from firm operating funds — append-only, fully audited
No transaction is ever edited or deleted -- entries are append-only. A mistaken entry is corrected by voiding it with a mandatory reason (the void stays visible in the record, it never disappears), never by silent edit or deletion. This is the real audit-trail requirement, not a UI convention.

Accounting (Operating)
Firm operating accounts — structurally separate from Trust Accounting, never linked or shared
This panel has no code path into or out of Trust Accounting's data -- separate localStorage keys, separate functions, no shared computation. That separation is deliberate and permanent, not an oversight to "connect later" -- mixing operating and trust funds is exactly what IOLTA rules exist to prevent.

The multiplier and every input here is editable, never a fixed formula presented as authoritative.
