AI Assistant
Powered by Claude · Citation-grounded — never presents an unverified case citation or statute as fact
This assistant will never output a specific case citation, statute citation, or docket number in citable- reference format (e.g. "384 U.S. 436 (1966)") -- not even for a famous case, not even paired with a disclaimer. It can describe a case narratively (the holding, the parties, the era, the legal principle) but always directs you to Westlaw, Lexis, or the court's own site for the actual citation. This is enforced by the system prompt below, not a UI label bolted onto unverified output.

Trust Accounting (IOLTA)
Client funds, tracked completely separate from firm operating funds — append-only, fully audited
No transaction is ever edited or deleted -- entries are append-only. A mistaken entry is corrected by voiding it with a mandatory reason (the void stays visible in the record, it never disappears), never by silent edit or deletion. This is the real audit-trail requirement, not a UI convention.
Three-Way Reconciliation
The three balances below are computed by exact arithmetic on the real transaction records, never by an AI model -- an LLM verifying its own numeric claim is exactly the failure mode this app's AI Assistant is built to avoid elsewhere. "AI-verified" here means the Explain button below can ask Claude to describe a detected mismatch in plain language after the real computed check has already found it, not that the AI performs the comparison itself.

Document Management
Matter-centric filing, OCR on uploaded scans, email filing, full version control
OCR runs entirely in your browser via Tesseract.js (loaded on demand, no server upload) -- the extracted text is what gets saved and versioned, not the original image (no cloud file storage is wired up yet, so large binary files aren't persisted here). Email filing is manual logging, not live inbox sync -- paste in what you want filed against the matter.

Accounting (Operating)
Firm operating accounts — structurally separate from Trust Accounting, never linked or shared
This panel has no code path into or out of Trust Accounting's data -- separate localStorage keys, separate functions, no shared computation. That separation is deliberate and permanent, not an oversight to "connect later" -- mixing operating and trust funds is exactly what IOLTA rules exist to prevent.

Personal Injury Module
Case value estimation, medical records/lien tracking, settlement calculation
Case value estimation uses the real, commonly-taught "multiplier method" (non-economic damages estimated as economic damages × an editable multiplier) -- an estimation heuristic used in PI practice, not a guaranteed or formulaic settlement value. The multiplier and every input here is editable, never a fixed formula presented as authoritative.
