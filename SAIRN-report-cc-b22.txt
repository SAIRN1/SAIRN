H1's b63 finding. THE ROOT CAUSE IS NOT THE CASE-SENSITIVITY -- it is that ONE
QUESTION HAD TWO ANSWERS a hundred lines apart:

    labels = [... if BP.BOARD_TOKEN[l] in agents or l in agents]  # label OR token
    nonce  = nonce if (agents and token in agents) else None      # token ONLY

BOARD_TOKEN['H1'] is 'h1'. So `--agent H1` matched the first expression on the
LABEL and failed the second on the TOKEN: the row was checked, the nonce was
dropped, and the summary printed

    CLEAN: ... and the nonce crossed both ends

because that sentence was keyed on a nonce having been SUPPLIED rather than
CHECKED. That substitution is what made a skipped check read as a verified
pass, and it is the part worth remembering: the wrong word in a summary turned
a silent skip into an assertion.

     Case-insensitive on both label and token, surrounding whitespace
     tolerated, and a whitespace-only --agent selects nothing rather than
     everything.

     `nonce_checked`, and names it. A nonce supplied and checked on no row
     prints a loud line saying it should be unreachable since b22 and that the
     two sites have drifted apart again if you are reading it.
  3. AN `--agent` MATCHING NOTHING IS COULD NOT RUN, EXIT 2, naming the valid
     names in both forms. Before b22 it fell through to
     "0 FINDING(S) across 0 agent(s)" and then printed CLEAN at exit 0 -- a
