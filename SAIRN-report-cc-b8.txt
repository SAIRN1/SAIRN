3. THE STATUS LINE: A PERCENTAGE, AND A ?? WHEN IT CANNOT TELL
--------------------------------------------------------------------------------
    python tools/sairn_status_line.py --fixtures   -> 21/21, exit 0
    live render against this session's transcript:
      cc | Opus 5 (1M) | ctx 33% of 1000k

One USER-LEVEL `statusLine` entry in ~/.claude/settings.json covers ALL SIX
agent folders. That is the whole reason it is there and not in six project
settings files: nothing is written into another agent's clone, and the two
hover clones in particular are a boundary a build agent must not cross.

NOT A HOOK, and the difference is structural rather than a label: a status line
cannot block a tool call, cannot edit a file and cannot refuse anything. It
ALWAYS EXITS 0, because a non-zero status line prints a harness error over the
figure it exists to show -- and that in turn means it must never be cited as a
check, which is said in the file itself.

THE NUMBER IS A FRACTION BECAUSE THE CEILING MOVES. 840,000 tokens is a
catastrophe in a 200K window and 84% in a 1M one. 1M for a [1m] model id, or
when `exceeds_200k_tokens` is true -- a session that has already passed 200K
cannot be a 200K session, which is a measurement rather than an assumption.

THERE IS NO CONTEXT FIELD IN THE PAYLOAD, so the figure is read from the LAST
`message.usage` in the transcript: input + cache_read + cache_creation. Output
tokens are NOT added -- they are already inside the next turn's input and
adding both double-counts. The transcript is scanned from the END in a bounded
window (256KB, then 4MB once), because reading a multi-megabyte append-only
file to find its last line is how a status line becomes the slowest thing in
the session.

AND 0% WOULD BE THE WORST POSSIBLE OUTPUT, so it is not reachable: a fresh
session with no usage line, an absent transcript, a line truncated mid-append
and an all-zero usage block each print `ctx ??%` with the reason. Four of the
21 fixtures are that path, and one asserts the ??-line carries no digit
percentage anywhere.

THE THRESHOLD IS LOCKED TO THE DISPLAY, which is the fixture worth copying:
138,000 of 200,000 prints `ctx 69%` and is NOT red; 140,000 is exactly 70% and
IS red (the boundary is >=, not >); and 139,000 -- 69.5% -- prints as `70%` and
must therefore ALSO be red, because a line reading `70%` in plain text would be
worse than either answer alone. The first draft of that fixture asserted the
opposite and FAILED on the first run, which is how the rounding question got
decided instead of assumed.

ONE DEPENDENCY, STATED: the script lives in the cc clone, so if
Documents\SAIRN-cc is moved the status line goes blank. Cosmetic; it fails no
command.
