2.1 THE DEFECT, REPORTED AND LEFT IN PLACE

    constraint rtroutes_saved_sane
      check (saved_seconds is null or saved_seconds >= 0),

THE MODULE DELIBERATELY RETURNS NEGATIVE SAVINGS UN-CLAMPED. From routes.js:
"A NEGATIVE RESULT IS RETURNED AS-IS AND IS NOT CLAMPED. A nearest-neighbour
heuristic can genuinely produce a worse path than the one a human chose, and a
caller that stores a negative saving has learned something true. Clamping is
how the original lost the distinction in the first place."

A test arm asserts the result IS negative. All four consumers render it --
"this order is about N min LONGER than the one you had."

SO IF THE HANDLER BRANCH EVER STORES A NEGATIVE, POSTGRES REJECTS THE ENTIRE
UPSERT and the route write fails.

NOT FIXED, ON PURPOSE. The instruction scoped fixes to column-name and type
mismatches; this is neither. THE CORRECT FIX IS TO DROP THE CONSTRAINT, not to
clamp the module -- clamping re-introduces the exact 2026-06-18 defect the
module was written to avoid, where an unmeasurable route and an already-optimal
one both rendered "0 min".

NOT REPRODUCED, AND THAT IS STATED: the tables do not exist, so no insert was
attempted. The contradiction is read from the schema text and the module
source, not from a failed write.
