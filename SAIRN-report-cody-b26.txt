THE TWO CONCEPTS, stated above the code in api/sd-data.js itself:

  READ SIDE: a read that could not be performed is not an empty table, so a 400
  is classified BEFORE any `provisioned: false` is sent -- an undefined-column

  WRITE SIDE: a row the table refused ON CONTENT is not a missing table, so the
  guard routes through the classifier this file already ships instead of
  answering 503 unconditionally and telling the operator to re-run a migration
  that is already applied.
