Selecting a catalog model is not a reservation. Reserving a specific physical unit is — the same non-fungible-item mechanism as StoneDesk's slab reservation and SAIRNdesign's one-of-a-kind item reservation: once a unit is reserved for one family, this app will not knowingly let it be reserved for a second family. Corrected 2026-08-09: the re-check right before saving happens against this device's own local data, not a server-side check — there is no server route for reservation data yet, so two staff on two different devices can still both reserve the same physical unit if their local copies haven't synced with each other. Treat this as a same-device safeguard only until real server-side reservation locking is built.
