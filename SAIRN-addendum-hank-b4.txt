WHY THIS FILE EXISTS

SAIRN-report-hank-b4.txt carries a SHA256 of its own body. Editing it to record
the shas of the commits that landed AFTER it would invalidate that hash, and
re-stamping a hash to accommodate a later edit makes the hash mean nothing. So
the three bookkeeping commits that followed the report are recorded here
instead.

It is also the honest answer to a thing this batch spent its length on: a
document that asserts a state it can no longer observe. The report's GIT STATE
block was true when it was written and could not name its own commit. This
addendum names it.

THE TERMINAL SHA IS STILL NOT IN HERE, and that is not an oversight -- the
commit that adds this file cannot know its own sha either. The chain below ends
at the last sha that existed when this was written; `git log origin/main` is the
authority past that point, as it always was.
