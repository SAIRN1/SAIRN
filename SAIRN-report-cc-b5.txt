THE SYNTAX, PRECEDENCE AND COMPOUND BEHAVIOUR WERE VERIFIED AGAINST THE CURRENT
DOCUMENTATION BEFORE A RULE WAS WRITTEN. The facts that shaped them:
  * `Bash(rm *)` and `Bash(rm:*)` are IDENTICAL; `:*` is recognised only at the
    end, so one form is used throughout and the two are never mixed.
  * THE SPACE BEFORE A TRAILING `*` IS LOAD-BEARING. `Bash(ls *)` does not
    match `lsof`; `Bash(ls*)` does. Delete rules carry both spellings.
  * DENY ALWAYS WINS, at every settings level, and an allow can NEVER carve an
    exception out of a deny. This is what makes `Bash(git push *)` safe to
    allow while every force spelling is refused.
  * A compound command is SPLIT and each subcommand matched independently,
    including inside `$( )`.
  * Deny rules match PAST a leading env assignment; allow rules are documented
    not to.
  * Read/Edit deny covers Bash redirects and cat/sed/tee, but NOT a subprocess
    that opens the file itself.

EVERY CLASS WAS DRIVEN WITH A HARMLESS MATCHING COMMAND. The rules took effect
